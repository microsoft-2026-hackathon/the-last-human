# 3분 30초 발표 스토리보드 — The Last Human (v5)

**승인은 기록되지만, 이해는 기록되지 않는다.** The Last Human은 위험한 변경이 머지되기 전에 작성자가 코드에 대고 설명하게 하고, 그 확인을 커밋 SHA에 묶어 머지 조건과 모듈별 커버리지로 이어 준다. 금지가 아니라 확인이다.

## 1. v4와의 관계 — 이 문서가 다루는 것

| | [v4](storyboard-v4.md) | v5 (이 문서) |
| --- | --- | --- |
| 산출물 | 데모 **영상** 스토리보드 | **발표** 스토리보드 |
| 길이 | 120초 (15컷) | 210초 (3:30) |
| 데모 | 문서 전체가 데모 | 88초 슬롯 하나 — **이미 제작된 영상을 재생** |
| 아키텍처 | "슬라이드로 이동"이라고만 적힘 | 그 슬라이드를 여기서 확정 (simple · details 두 장) |
| 패키징 | 없음 | Quick start 슬라이드 신설 |
| 심사기준 | 고려 안 함 | **100점 배점에 슬라이드를 맞춤** (§2) |

v5는 v4를 대체하지 않는다. **v4는 영상 안을, v5는 영상 앞뒤를 설계한다.** 영상 내부의 컷·VO·테이크 상태는 v4가 단일 출처이며 여기서 다시 서술하지 않는다.

발표는 88초 데모를 가운데 두고 앞 68초 · 뒤 54초로 나뉜다. 앞은 데모를 **볼 준비**를 시키고, 뒤는 데모가 **증명하지 못한 것**을 맡는다. 이 분업이 v5의 전부다.

**#3(15점)이 가장 놓치기 쉽다.** "만들었다"만 말하면 0점 구간이다. 07과 10이 **가설·실험·측정·학습**을 한 쌍으로 보여 준다 — 07이 "우리 자신에게 걸었다"(실험), 10이 "그래서 못 잡는 걸 찾았다"(측정과 학습)를 맡는다.

## 4. 구성 — 서사

**개인의 속도 → 조직의 공백 → 그 공백이 이미 사고가 됐다 → 체크는 다섯 줄뿐 → 방향을 뒤집는다 → 무엇을 안 만드는지 → [데모] → 우리 자신에게 걸어 봤다 → 누가 쓰는가 → 어떻게 도입하나 → 무엇을 못 잡는가 → 기장은 사람.**

앞 68초의 과제는 **데모의 88초를 해설 없이 견디게 만드는 것**이다. 데모가 시작되면 발표자는 말하지 않는다. 그러려면 그 전에 관객이 세 가지를 알고 있어야 한다 — 초록 체크가 무엇을 보증하고 무엇을 안 하는지, 게이트가 왜 이 PR에서만 켜지는지, `Hold`가 감점이 아니라는 것. 06까지가 그 준비다.

뒤 54초의 과제는 **데모가 증명할 수 없는 것을 맡는 것**이다. 데모는 한 PR에서 제품이 동작함을 보여 줄 뿐, 반복해서 검증했는지(07), 누가 상태를 쓰는지(08), 남의 저장소에 걸 수 있는지(09), 무엇을 못 잡는지(10)는 화면에 나오지 않는다. 심사 배점 65점이 정확히 여기 있다.

## 6. 아키텍처 두 장 — 무엇을 나누나

한 장에 다 넣으면 12초 안에 읽히지 않고, 빼면 "봇이 자기가 통과시킨 것 아니냐"에 답할 수 없다. **읽는 시간이 다른 두 장**으로 나눈다.

| | 08 simple | A1 details |
| --- | --- | --- |
| 언제 | 본 발표 12초 | Q&A에서만 |
| 블록 수 | 4 (GitHub · Actions · Server · Model) | 9단계 데이터 흐름 + 신뢰 경계 4개 |
| 답하는 질문 | "누가 상태를 쓰나" | "왜 그걸 믿을 수 있나" |
| 한 문장 | 쓰기는 서버 하나, 검증은 Actions가 따로 | 비밀은 서버에만, Actions는 단기 OIDC만 |
| 심사기준 | #5 배포·확장 | #5 보안 |
| 출처 | [v4 §7](storyboard-v4.md) 런타임 흐름 | [v4 §7](storyboard-v4.md) 데이터 흐름 표 전체 |

두 장 모두 **인라인 SVG**로 그린다. 이미지 파일을 쓰지 않는 이유는 발표 화면 해상도가 확정되지 않았고, 다크/라이트 어느 쪽에서 띄울지도 현장에서 갈리기 때문이다.

simple에서 지켜야 하는 세 가지 — 상태 화살표가 **서버에서 GitHub으로만** 향하고, Actions에서 서버로 가는 선에 `OIDC`가 붙어 있고, 모델 블록이 **점선**(권한 없음)으로 그려질 것. 이 셋이 08의 발화와 1:1로 맞는다.

## 7. 데모 영상 인계 — 앞뒤의 계약

발표자가 데모에 개입하지 않으므로, 영상이 전제하는 것은 06까지 전부 깔려 있어야 한다.

**데모 시작 전에 관객이 알고 있어야 하는 것**

| 전제 | 어느 슬라이드가 책임지나 |
| --- | --- |
| 초록 체크는 이해를 보증하지 않는다 | 04 |
| 게이트는 AI가 썼는지가 아니라 위험도로 켜진다 | 05 (1단계) |
| `Hold`는 감점이 아니라 "한 곳 더 보라"는 안내다 | 06 |
| 새 커밋이 오면 확인이 무효가 된다 | 05 (4단계) |

**데모가 보여 주는 것** (상세는 [v4 §4](storyboard-v4.md))

토큰 갱신 PR → 초록 체크 다섯 줄 · 게이트만 대기 → 두 문항 → 첫째 Accepted, 둘째 **Hold** → 보류가 가리킨 옆 파일 `sample-app/app/http_client.py`에서 이미 있던 재시도 루프 발견 (**3 × 3 = 9**) → 수정 → 새 커밋이라 게이트가 다시 물음 → `Human-verified` → **사람이** 머지 → 저위험 문서 PR은 그냥 통과 → 대시보드의 `Can answer` 0 → 1.

## 8. 수치와 근거

### [저장소] 이 저장소에서 재현되는 것

발표 중 질문이 들어오면 그 자리에서 돌릴 수 있다.

```bash
PYTHONIOENCODING=utf-8 python docs/demo/presentation/verify_claims.py
```

| 주장 | 실측 | 근거 |
| --- | --- | --- |
| 데모 PR은 게이트가 켜진다 | **55 / 40 → 발동** (중요 경로 +30 · `except\s` +10 · `async`/`await` +15) | `.lasthuman.yml` + `risk.score()` |
| 저위험 문서 PR은 지나간다 | **0 / 40 → 미발동** | 같음 |
| 인증 경로 −2줄은 못 잡는다 | **30 / 40 → 미발동** | 같음. 10 슬라이드의 근거 |

**07의 "몇 번 막혔나"는 로컬에서 확인할 수 없다.** GitHub의 status 이력을 조회해야 하므로, 촬영 직전에 실제 값으로 채운다. 확인 전에는 화면에 숫자를 넣지 않는다.

## 10. Q&A 대비

배점이 큰 #4·#5부터 답을 준비한다.

| 질문 | 답 | 기준 |
| --- | --- | --- |
| "게이트도 AI한테 물어보면 되지 않나?" | 코드와 질문을 함께 주면 상당수 맞힌다 — 사실이다. 다만 **어떤 코드를 줄지 먼저 알아야** 한다. 질문은 특정 hunk를 가리키고 근거로 코드 위치를 요구한다. 목표는 부정행위 차단이 아니라 **승인 전 최소 한 번은 코드를 보게 만드는 것**이고, 지금은 그 한 번조차 없다. | #2 |
| "모든 PR을 막으면 개발이 마비되지 않나?" | 전수 적용하지 않는다. 임계값 미달은 `Not required`로 지나간다. 데모 안에서 문서 PR이 그대로 머지되는 장면으로 증명된다. | #2 |
| "모델이 죽으면?" | 사람을 막지 않는다. 미통과는 `failure`가 아니라 `pending`이다. **실패 방향에 일관성이 있다** — 사람이 답을 빠뜨리면 막고, 인프라가 죽으면 통과시킨다. | #5 |
| "보안은?" | App 개인키·client secret·모델 자격은 **서버에만** 둔다. Actions에는 넘기지 않고 단기 OIDC만 쓴다. 다만 "비밀이 전혀 없다"고는 말하지 않는다 — Actions도 단기 GitHub 자격은 갖는다. 코드와 근거는 모델에 전달되므로 민감정보 유입 방지와 모델 서비스의 보관 정책은 별도로 다룬다. | #5 |
| "확장성은? 서버 하나로 여러 저장소 되나?" | 지금은 **서버 1대 = 저장소 1개** 바인딩이다. 여러 저장소는 인스턴스나 설정을 분리한다. 패키징에서 정리 중인 항목이고, 숨기지 않는다. | #5 |
| "사내망에도 둘 수 있나?" | 웹훅 수신자가 아니라 **Relay** 구조라서 가능하다. self-hosted 러너와 사용자 접속 경로를 갖추면 서버를 사내망에 둘 수 있다. 대가는 러너 기동 지연 20–40초와 체크 목록 한 줄. | #5 |
| "Global 진출?" | GitHub PR 워크플로 위에서만 동작하므로 언어·지역 종속이 없다. 게이트 정책은 저장소의 `.lasthuman.yml` 한 파일이고, 규제가 강한 조직일수록 "머지 전 이해 기록"의 수요가 크다. 다만 현재 구조 분석은 **Python 중심**이고 UI 문구는 영어 기준이다. | #5 |
| "기간 내에 실제로 얼마나 만들었나?" | 커밋 109개, 머지된 PR 35개, 테스트 519개, 동작 중인 워크플로 4개. 코드 14,140줄에 테스트 12,801줄. 그리고 **그 PR들이 이 게이트를 통과했다.** | #4 #3 |
| "개인 평가로 쓰이지 않나?" | 개인 점수·순위·팀장 조회는 요청받아도 만들지 않는다. 대시보드는 이름이 아니라 **수**를 센다. 만드는 순간 다른 제품이 된다. | #2 |
| "CODEOWNERS가 있으면 담당자는 이미 있는 것 아닌가?" | 담당자가 적혀 있다는 사실이 그 코드를 **이해한 사람이 있다는 뜻은 아니다.** 대시보드는 선언된 담당 옆에 실제로 답할 수 있는 사람 수를 나란히 놓는다. 그 격차가 이 프로젝트가 드러내려는 것이다. | #1 |
| "우리 저장소에 얼마나 걸리나?" | 운영자가 App 등록·서버 배포·헬스 확인 3단계를 **한 번**. 저장소마다 App 설치 → 파일 3종 PR → 변수 → 첫 PR로 발행 확인 → **그다음에** 필수 체크. 순서를 바꿔 필수 체크를 먼저 걸면 발급자가 없어 머지가 영원히 막힌다. | #5 |

## 11. 레드라인 점검

발표 자료가 [AGENTS.md](../../AGENTS.md)의 금지 넷을 넘지 않는지 슬라이드 단위로 확인한다. **심사 점수를 올리려고 이 넷을 넘지 않는다** — 넘는 순간 다른 제품이 된다.

- [x] 개인 점수·등급·순위가 어느 화면에도 없다 — 대시보드는 구역별 **수**만 보여 준다
- [x] 사람 이름이 붙은 집계가 없다 — CODEOWNERS 담당자는 "선언된 담당"이지 성과 지표가 아니다
- [x] 감점·보류 이력이 화면에 남지 않는다 — 데모의 `Hold`는 진행 중 상태이고 기록으로 쌓이지 않는다
- [x] 팀장 조회 화면이 없다 — A1의 `Org / leads`는 같은 대시보드를 읽을 뿐 개인 이력 조회가 아니다
- [x] AI 탐지로 발동한다는 표현이 없다 — 05의 1단계는 위험도다
