## 배경

`ensureFresh()`가 토큰 갱신에 실패하면 그대로 예외를 던지고 있었습니다. 인증 서버가 순간적으로 429나 503을 돌려주는 경우가 주중 피크 시간대에 하루 20~40건 관측되며, 그때마다 요청 전체가 실패합니다. 실제로는 수백 밀리초 뒤 재시도하면 대부분 성공하는 상황입니다.

## 변경 내용

일시적 실패를 영구 실패와 분리하고, 일시적 실패에 대해서만 **지수 백오프로 최대 3회까지 재시도**하도록 했습니다.

- `MAX_RETRIES = 3` — 시도 횟수 상한. 3회를 넘기면 호출자에게 실패를 전파합니다.
- `BASE_BACKOFF_MS = 200` — 기준 간격. `backoffFor(attempt)`가 `200ms → 400ms → 800ms`로 간격을 넓힙니다.
- `HttpError.transient`로 429/500/502/503/504만 재시도 대상으로 분류합니다. 401/403 같은 영구 실패는 즉시 던집니다.

재시도가 모두 소진되기 전까지는 호출자가 실패를 보지 않으므로, `src/auth/session.js`와 `src/orders/service.js` 쪽은 변경이 필요 없습니다.

## 왜 지터를 넣지 않았나

인스턴스 수가 아직 4대라 동시 재시도가 몰려도 인증 서버가 감당하는 범위입니다. 오토스케일링을 켜는 시점에 지터를 추가하는 쪽이 낫다고 판단했습니다.
